== Use-Case: UC02 Los bewegen
=== Kurzbeschreibung

Der Use Case beschreibt die Operation, die Lose auf den jeweils nächsten Fertigungsprozess setzen kann.

=== Kurzbeschreibung der Akteure

==== Mitarbeiter an der Maschine

Möchte manuell Los auf nächsten Arbeitsschritt bewegen

==== Abteilungsleiter

Möchte experimentell manuell Los in anderen Arbeitsschritt einfügen

==== Timer



=== Vorbedingungen
//Vorbedingungen müssen erfüllt, damit der Use Case beginnen kann, z.B. Benutzer ist angemeldet, Warenkorb ist nicht leer...

*Vorbedingung 1:* Los ist in Zustand "completed".
 
=== Standardablauf (Basic Flow)
//Der Standardablauf definiert die Schritte für den Erfolgsfall ("Happy Path")

1. Der Use Case beginnt, wenn Mitarbeiter, Abteilungsleiter manuell auf Benutzeroberfläche Anweisung gibt, ein Los bewegen zu wollen
2. Zustand von Los wird überprüft
3. Wenn Los Zustand "completed" ist , dann wird Los auf nächste Operation und Zustand "wartend" oder "finished" gesetzt
4. Der Use Case ist abgeschlossen.

// warte Zustand :
// War in bearbeitung -> wartend
// los war nicht  ncith in Bearbeitung -> wartend
// man weis nicht ob das Los schon bearbeitet wurden, da beise den gleichen Zustand haben
// es braucht einen Zustand wartend vor der Bearbeitung und einen Zustand wartend nachher
// wartend - zu bearbeiten
// completed - wurden bearbeitet und wartet darauf, dass die auf die nächste Operation/Maschine/produktionsschritt gepackt werden

// dieser Zustand macht: bewegen macht schauen ebi Losen von Completed was als nächstes passiert

// geht von complet bei der nöchsten Operation in den ZUstand wartend oder fertig gesetzt

// gestartet geht automatisch in wartend über

=== Alternative Abläufe
//Nutzen Sie alternative Abläufe für Fehlerfälle, Ausnahmen und Erweiterungen zum Standardablauf
==== Alternativer Ablauf 1

Mithilfe des Timers können automatisch Lose bewegt werden. 
. Der Use Case wird in Schritt 2 fortgesetzt.

==== Alternativer Ablauf 2

Wenn Abteilungsleiter im Schritt 3 sieht, dass das Los entweder im Zustand "wartend" oder "hold" ist, dann kann er das Los auf beliebigen Status setzen und bewegen.
. Der Use Case ist abgeschlossen.

// geht so nicht 
// manuelles Bewegen von Losen geht nur von Losen die im Zustand wartend sind!
// oder im Zustand hold ist
// Abteilungsleiter kann dann dort den Zustand beliebig ändern und irgendwo hin tuen (Operation)
// und manuell von wartend auf hold setzen
// man kann die Lose nur manuell zwischen wartend und hold wechseln keine anderen Zustände

==== Alternativer Ablauf 3

Wenn Mitarbeiter im Schritt 3 sieht, dass Los entweder im Zustand "wartend" oder "hold" ist, dann kommt eine Fehlermeldung, dass es aktuell keine manuell zu bewegenden Lose gibt.
. Der Use Case ist abgeschlossen.

// macht so auch keinen Sinn
// was sinn macht, ist einen Meldung es gibt gerade keine manuell zu bewegenden Lose 
// überarbeiten und dann an Ringel schicken -> davor muss natürlich das Zustanddiagramm angepassst werden
