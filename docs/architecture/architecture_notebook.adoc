Das System ist eine Datenbankanwendung für die Visualisierung und Verwaltung von Prozessschritten einer Halbleiterfabrik. Diese soll für mehrere Jahre nutzbar sein. Außerdem ist die Weiterentwicklung dieses Systems durch zukünftige Gruppen geplant. Dadurch soll die Architektur darauf abzielen, eine langlebige, erweiterbare und robuste Datenbankanwendung zu bieten, welches auch bei Abstürzen resistent gegenüber Datenverlust ist.

Für die intuitive Bedienung der Anwendung sollen die Prozesse und Datenausgabe übersichtlich und verständlich dargstellt werden. Hierzu sind einfache Bedienelemente zu verwenden, welche die Möglichkeiten für Fehlentscheidungen der Nutzer minimieren. Die Anwendung soll in verschiedenen Browsern nutzbar sein.

Da die Anwendung auf einem Raspberry Pi betrieben wird, ist die Architektur darauf ausgelegt, die Ressourcen des Raspberry Pi möglichst effizient zu nutzen. Es sollen größere Mengen an Daten verarbeitet werden können, ohne dass die Anwendung abstürzt oder die Performance stark beeinträchtigt wird. So ist eine gut skalierbare Datenbankanwendung zu entwickeln.

== Architektur-relevante Anforderungen

*Funktional*

* *SWFA-1:* Das System muss Zugriffsbeschränkungen gewährleisten, da nicht jeder Anwender jeden Use Case ausführen darf.
* *SWFA-2:* Das System muss zeitgesteuerte Aktivitäten in Form eines Timers ermöglichen, da Statusabfragen der Lose und Maschinen ausgewertet werden müssen.

* *SWFA-5:*  Das System muss Daten aus einer Datenbank auslesen können. 

*Effizienz (Performance)*

* *QAGE-1:* Das System soll beständig gegen einen Ausfall bei einer hohen Anzahl gleichzeitiger Nutzer sein.
* *QAGE-2:* Das System soll in wenigen Sekunden dem Anwender eine Antwort geben.
* *QAGE-3:* Das System soll ein Backup in wenigen Minuten erstellen können.

*Wartbarkeit (Supportability)*

* *QAGW-2:* Das System muss kompatibel zu Chrome, Firefox, Edge und Safari sein.
* **QAGW-1:** Das Entwicklerteam muss eine (fortgeführte) Entwicklerdokumentation bereitstellen, welche die Weiterentwicklung des Systems ermöglicht.

#### Zuverlässigkeit (Reliability)

* **QAGZ-1:** Das System muss robust gegen Abstürze und Datenverlust sein. Zur Überprüfung wird das System unerwartet heruntergefahren.
* **QAGZ-2:** Das System kann mithilfe von Backups Daten wiederherstellen.
* **QAGZ-3:** Das System muss jederzeit abrufbar sein.

#### Benutzerfreundlichkeit (Usability)

* **QAGU-1:** Alle Prozesse und Datenausgaben müssen übersichtlich, eindeutig und verständlich sein.

* **QAGU-1.6:** Das System muss verständliche Fehlermeldungen gewährleisten.

* **SWFA-3:** Das System muss verständliche Fehlermeldungen gewährleisten. Zur Überprüfung werden beim manuellen Bearbeiten eines Loses falsche Eingaben getätigt.

## Persistenz (Persistence)
- **Zweck:** Lesen und Schreiben von gespeicherten Daten.
- **Eigenschaften:** Unterstützt die dauerhafte Speicherung von Daten.
- **Funktion:** Verwendung eines relationalen DBMS (PostgreSQL) zur Datenpersistenz.
- **Zugehörige SWFA:** SWFA-3

## Sicherheit (Security)
- **Zweck:** Schutz des Zugriffs auf Ressourcen oder Informationen.
- **Eigenschaften:** Beinhaltet Authentifizierung, Autorisierung und Datenverschlüsselung.
- **Funktion:** Gewährleistung der Datensicherheit und des beschränkten Zugriffs basierend auf Benutzerrollen.
- **Zugehörige SWFA:** SWFA-1

## Transaktionsmanagement (Transaction Management)
- **Zweck:** Handhabung von ACID-Transaktionen.
- **Eigenschaften:** Unterstützt die Integrität und Zuverlässigkeit von Datenbankoperationen.
- **Funktion:** PostgreSQL bietet native Unterstützung für Transaktionsmanagement, um Konsistenz und Zuverlässigkeit der Daten zu gewährleisten.

## Mega-Daten (Mega-data)
- **Zweck:** Unterstützung für die Verarbeitung sehr großer Datenmengen.
- **Eigenschaften:** Skalierbare Datenverarbeitung und -speicherung.
- **Funktion:** PostgreSQL und Python-Middleware für effiziente Handhabung und Verarbeitung großer Datensätze.
- **Zugehörige SWFA:** QAGE-4

## Terminierung (Scheduling)
- **Zweck:** Ermöglicht die Planung und Ausführung von Aufgaben zu bestimmten Zeiten oder unter bestimmten Bedingungen.
- **Eigenschaften:** Unterstützt zeitgesteuerte und ereignisbasierte Aufgaben. Flexibel einsetzbar für regelmäßige oder einmalige Ereignisse.
- **Funktion:** Im System ermöglicht dies die Automatisierung von Datenerfassung und Wartungsaufgaben, für zeitgesteuerte Datenbank-Updates.
- **Zugehörige SWFA:** SWFA-2

## Archivierung (Archiving)
- **Zweck:** Verschieben von Daten aus dem aktiven Speicher, wenn sie einen bestimmten Zustand erreicht haben.
- **Eigenschaften:** Unterstützt Langzeitspeicherung und Entlastung des aktiven Speichers.
- **Funktion:** Automatisiertes Verschieben alter oder selten genutzter Daten in Archivspeicher.
- **Zugehörige SWFA:** SWFA-3

## Fehlermanagement (Error Management)
- **Zweck:** Erkennung, Weiterleitung und Berichterstattung von Fehlern.
- **Eigenschaften:** Robuste Fehlerbehandlung und klare Benachrichtigungssysteme.
- **Funktion:** Implementierung eines Systems, das Fehler effektiv erkennt und dem Benutzer verständliche Meldungen liefert.
- **Zugehörige SWFA:** QAGU-1.6

## Lokalisierung / Internationalisierung (Localization / Internationalization)
- **Zweck:** Unterstützung mehrerer menschlicher Sprachen und Darstellung der vom Benutzer bevorzugten Sprache.
- **Eigenschaften:** Flexibilität in der Sprachwahl, einfache Anpassung an verschiedene Sprachen.
- **Funktion:** Implementierung eines Systems, das Benutzeroberflächen und Meldungen in verschiedenen Sprachen unterstützt.
- **Zugehörige SWFA:** QAGU-1.4

Diese Architekturmechanismen sind essentiell für die Entwicklung einer robusten, sicheren und skalierbaren Datenbankanwendung, die auf einem Raspberry Pi mit Raspbian Betriebssystem betrieben wird.

== Wesentliche Abstraktionen
//[List and briefly describe the key abstractions of the system. This should be a relatively short list of the critical concepts that define the system. The key abstractions will usually translate to the initial analysis classes and important patterns.]

Die Architektur zielt darauf ab, eine langlebige, erweiterbare und robuste Datenbankanwendung zu bieten, die große Datenmengen verarbeitet und auf verschiedenen Endgeräten nutzbar ist. Folgende Schlüsselabstraktionen sind identifiziert:

- **Datenbank-Server (PostgreSQL):** Zentral für die Datenspeicherung und -organisation, ausgewählt für seine Skalierbarkeit und Effizienz auf dem Raspberry Pi.
- **Middleware (Python-Anwendung):** Verbindet die Datenbank mit der GUI, nimmt Anfragen entgegen, führt Datenbankoperationen durch und gibt Ergebnisse zurück.
- **Benutzeroberfläche (Flask-UI):** Flask stellt eine Webanwendung bereits, welche mittels HTML-Templates und CSS-Stylesheets die Interaktion der Endbenutzer mit dem System über eine benutzerfreundliche Web-GUI ermöglicht.
- **Schnittstellen und Routen:** Wichtig für die Kommunikation zwischen den verschiedenen Systemkomponenten.

== Schichten oder Architektur-Framework
//[Describe the architectural pattern that you will use or how the architecture will be consistent and uniform. This could be a simple reference to an existing or well-known architectural pattern, such as the Layer framework, a reference to a high-level model of the framework, or a description of how the major system components should be put together.]
Die Architektur basiert auf einem mehrschichtigen Framework, das Folgendes umfasst:

### Datenbankebene (PostgreSQL)
- **Verantwortlich für die Speicherung und das Management der Daten**, mit Fokus auf Effizienz und Skalierbarkeit für den Einsatz auf einem Raspberry Pi.

### Middleware-Ebene (Python)
- **Python-Anwendung:** Dient als zentrale Vermittlungsstelle zwischen Datenbank und Benutzeroberfläche.
- **Datenbankzugriffsschicht:** Nutzt die Psycopg2-Bibliothek zur Interaktion mit PostgreSQL.
- **Logikschicht:** Beinhaltet die Geschäftslogik, Datenvalidierung und -aufbereitung.

### Benutzeroberflächenebene (Flask-GUI)
- **Flask als Web-Framework:** Vereinfacht die Erstellung und Verwaltung von Webanwendungen.
- **Schnittstellen und Routen:** Definieren den Zugang zur Middleware und ermöglichen die Benutzerinteraktion.

### Schnittstellen
- **Datenbank-Middleware-Schnittstelle:** Sicherer Datenaustausch über Psycopg2.
- **Middleware-GUI-Schnittstelle:** RESTful API-Endpunkte für die GUI-Kommunikation.
- **Benutzeroberfläche-Endbenutzer-Schnittstelle:** UI mittels HTML-Templates, CSS-Stylesheets und gegebenenfalls JavaScript-Code für die Interaktion mit dem Endbenutzer.

Diese Architektur fördert die langfristige Nutzbarkeit und Weiterentwicklung der Anwendung, selbst auf einem Raspberry Pi mit begrenzten Ressourcen.
